# История версий

## zapret-rust 1.4 — 28 ноября 2026

- Исправлен трекер Windows. При загрузке данных он мог показывать ноль полученных байт, даже когда NBA 2K27 скачивала контент. Трекер учитывает оба порядка адресов в событиях TCP для IPv4 и IPv6. В пункте **8 → 1** видны объёмы приёма и отправки по каждому соединению.
- При обработке сетевой записи трекер накапливает счётчики численно и форматирует адреса и время один раз на соединение. Полный набор автоподбора также проверяет изображение одежды NBA 2K27 размером 305 259 байт по SHA-256.

- При подборе стратегии и проверке ПК zapret проверяет сервис входа Epic по его публичным ключам. Проверка ПК отдельно показывает результат через настройки прокси Windows. Если для выбранной NBA 2K27 включено закрепление серверов, zapret повторяет запрос к проблемным адресам, оставляет проверенный адрес при частичном отказе и возвращается к DNS после восстановления. Ручные записи Epic в hosts имеют приоритет.
- Проверка ПК загружает файл магазина NBA 2K27 напрямую и, при настроенном прокси или автонастройке, через сетевые настройки Windows. Для каждого маршрута она сверяет размер и SHA-256. При включённом закреплении игровых адресов запись CDN для выбранной NBA 2K27 обновляется только после успешной загрузки файла с конкретного IP. Если проверка не удалась на всех адресах, прежние записи сохраняются.
- Если GitHub недоступен напрямую, обновление может получить сведения о релизе и архив через прокси Windows. Программа сверяет размер и SHA-256 архива.
- Проверка HTTP/2 пробует другой адрес сайта, если первый завершил TLS, но предложил только HTTP/1.1.
- Пункт **8 → 13** проверяет воспроизведение ролика YouTube и считает показанные кадры. В **8 → 12** можно отметить слышимость в каждом направлении после обмена фразами в Discord.
- Если провайдер возвращает несколько адресов, проверка путей IPv4 и IPv6 учитывает запасной адрес каждого семейства. Голосовая диагностика Discord также проверяет запасные адреса STUN в пределах времени одного замера.
- Встроенная проверка HTTP/3 продолжает поиск рабочего адреса после отказа TLS на одном узле. Для успешного результата другой узел должен предъявить действительный сертификат для того же имени.
- При зависании TLS на одном из адресов сайта HTTPS-проверки, загрузка списков и защищённые соединения моста Telegram могут завершить соединение по другому адресу из DNS в пределах того же таймаута. Это работает и с двумя адресами одного семейства, и с сочетанием IPv4 и IPv6.
- Сравнение HTTP/1.1 в диагностике учитывает запасные адреса. Автоподбор сохраняет замер задержки исходного адреса, если тот успел подтвердить TLS первым.

## zapret-rust 1.3 — 26 ноября 2026

- Первый запуск обновляет списки и запускает проверку совместимости. Архив содержит готовый список IP для работы без сети. Главное меню открывает `zapret-rust.exe`.
- В свойствах EXE Windows отображаются версия и описание zapret-rust.
- Для каждого из шести общих списков загрузчик проверяет ответ GitHub Raw или API и при необходимости использует сетевые настройки Windows. При сбое обновления остаются доступными локальные списки. При первом открытии программа восстанавливает отсутствующие общие файлы из сборки. Автоподбор по расписанию может продолжить измерения с рабочими локальными списками.

- При отказе TLS на одном адресе HTTPS-пробы и встроенный загрузчик проверяют другие адреса из DNS. Ошибка согласования HTTP/3 на одном узле также допускает проверку другого узла. Адрес с неудачным исходным замером больше не закрепляется на весь круг автоподбора.
- При массовых таймаутах подбор повторяет запросы на выборке из разных сервисов. Два подтверждённых восстановления запускают повтор остальных сетевых отказов с меньшим числом одновременных запросов.
- При краткой ошибке DNS автоподбор повторяет запрос. Для выбора профиля нужны два разных контрольных сервера с успешным HTTP-ответом. Если один контрольный сервер недоступен до проверки профиля, его может заменить проверенный запасной. Для контрольных файлов проверяются заданные код ответа, размер и контрольная сумма.
- Если дополнительный тестовый профиль завершился при отборе, подбор пропускает его и записывает причину. Если к последнему кругу ни одна альтернатива не прошла проверку надёжности, прежний рейтинг сохраняется. При смене сети во время сохранения восстанавливаются предыдущие настройки и рейтинг.
- Если во время автоподбора Windows кратко потеряла исходное подключение, подбор один раз начинает измерения заново после его восстановления. Причину последней сетевой остановки показывают пункты 3 → 5 и 8 → 4.
- Автоподбор v8 оценивает повторяемый выигрыш отдельно для каждого сервиса в двух порядках проверки. В коротком отборе учитывается доля доступных адресов внутри каждого сервиса и сохраняется кандидат для каждого обнаруженного восстановления.
- Короткий отбор проверяет до четырёх контрольных адресов. Если один перестал отвечать, его можно заменить проверенным запасным адресом. Для продолжения нужны два независимых контрольных сайта.
- Мост Telegram при пустом пуле пробует оба адреса WebSocket для медиа. Пункт 4 → 4 показывает время ответа медиа-центров DC2 и DC4.
- Соседние профили используют общую контрольную проверку при стабильной сети. Долгие запросы из исходного замера стартуют в начале очереди при полной проверке профиля.
- Добавлены SOFT-TCP для прямого UDP и WHITE-06-WEB для прямых дополнительных игровых портов. Оба доступны в ручном выборе и автоподборе.

- Перед сменой стратегии автоподбор подтверждает выигрыш на тех же сервисах в обоих порядках. Быстрый режим сокращает набор адресов для первичного отбора.
- Иконка Roblox проверяется по свежему адресу с декодированием PNG. В меню моста Telegram добавлены проверки маршрута к медиа-центру и загрузки стикера тестовым ботом.
- При изменении сети автоподбор сохраняет причину в отдельный отчёт. Замеры используют уведомления Windows и сверяют состояние сети перед применением результата.

- Проверки сервисов и мост Telegram учитывают оба семейства IP даже при длинном ответе DNS. Медленный первый адрес получает время до общего таймаута запроса, пока параллельно проверяются запасные.
- Автоподбор сохраняет контекст при смене частного IPv4-адреса по DHCP в той же подсети с прежними шлюзом и профилем Windows. В пункте **6** сравниваются ответы A и AAAA. Для сервера иконок Roblox и других проверяемых имён показывается, когда Windows не получила IP, а адрес из защищённого DNS прошёл проверку сертификата.
- Автоподбор сравнивает скорость профилей по группам сервисов. Результаты показывают пробный балл относительно опорного профиля и баллы финальных сравнений. Для перехода по скорости нужны два выигрыша от +3 баллов с сохранением доступности сервисов.

## zapret-rust 1.2 — 24 ноября 2026

- Автоподбор продолжает измерение при обновлении временных IPv6-адресов в той же подсети. После сбоя чтения параметров Windows он повторяет опрос. При изменении подключения сообщение указывает, какие параметры изменились.

- При стандартных настройках мост Telegram держит до восьми соединений для файлов и четырёх для обычных сообщений на каждый настроенный дата-центр. Если все соединения заняты, мост одновременно пробует медиацентр и запасной маршрут. Резервный HTTP/2-транспорт освобождает слоты для новых частей файла при поступлении следующего запроса.
- Проверка ПК и автоподбор загружают файл с `media.discordapp.net` и сверяют его SHA-256. Проверка ПК сравнивает DNS с адресом из списка Discord и позволяет закрепить адрес для медиа отдельно от основного сайта.

- Автоподбор начинает замер сразу после подтверждения готовности Windows-движка. Для движков прежних версий сохранена двухсекундная пауза.
- В движке Windows ускорен поиск в кэшах IP и ошибок по доменам. При периодической очистке движок просматривает ещё действующие записи подряд и передаёт на удаление только записи с истёкшим сроком.

- При подготовке запуска контроллер использует контрольные суммы уже открытых файлов пакета. Совместимость сохранённого рейтинга проверяется сначала по сети. Для текущей сети по-прежнему сверяются файлы и настройки. Списки автосмены собираются без копирования содержимого каждого профиля.
- По результатам повторных проверок ALT3, ALT4, ALT9 и ALT21 перенесены в архив исходников. В штатном наборе 34 стратегии. Профили ALT1 и ALT13 сохранены для сетей, где они давали лучший результат.
- У основной стратегии `SOFT-STUN2` число повторов для начального пакета QUIC снижено с 11 до 4. В профиле `SOFT-WEB` число повторов на действие снижено до четырёх для TLS и QUIC и до трёх для голоса Discord. При автосмене нативный движок пропускает одинаковые наборы штатных действий для одного протокола и семейства IP.
- В меню выбора стратегий появились `SOFT-WEB` (75) для сайтов и Discord и `WHITE-TCP-LITE` (76) для тех, кому также нужен игровой TCP. Дополнительные игровые UDP-порты в этих профилях проходят напрямую.
- В нативной сборке фильтр WinDivert объединяет пересекающиеся диапазоны портов. Распознавание начальных пакетов QUIC для веб-профилей ограничено UDP/443. Игровые и голосовые правила получают трафик на своих портах независимо.
- Автосмена быстрее находит недавно использованные сайты и сохраняет историю выбора стратегий. Память под записи выделяется по мере заполнения кеша. Ранее сохранённая история читается в прежнем формате.

## zapret-rust 1.1

- Быстрый автоподбор для Windows сравнивает до 18 профилей на наборе из 86 целей. В набор входят обычные HTTPS-запросы, HTTP/3, изображения Discord и магазина NBA 2K, миниатюры YouTube и контрольные загрузки.
- При сравнении профилей внутри круга используются адреса, полученные на исходной проверке. В финале снова запрашивается DNS. Если адрес сервера сменился, дополнительная проверка помогает отличить сбой конкретного адреса от ухудшения при смене профиля.
- В консоли рядом с числом ответов теперь видна разница с пробой без обхода. Балл для выбора кандидата показан отдельно. В итоговой таблице свой цвет получают пройденный и проваленный финал.
- Во время замеров выделение мышью в классической консоли Windows временно отключается. Рабочий прогон больше не останавливается после случайного щелчка. Ctrl+C отменяет измерение и возвращает управление в меню.

## zapret rust 1.0

- Первый релиз Rust-линейки для Windows x64. Встроенные стратегии запускаются без файлов Lua. Пользовательские сценарии поддерживает Luna Core.
- Меню, управление службой, обновление с проверкой SHA-256 и локальный прокси Telegram работают в нативном приложении.
- Windows-пакет доступен в ZIP, RAR и 7z. Linux-установщик загружает зафиксированный upstream zapret2 v1.0.7 и сверяет SHA-256.
- Обновления Rust-линейки проверяются в репозитории zapret-rust.

## zapret-rust v0 — разработка перед первым релизом

- В поставке осталось 36 стратегий. Пять профилей (ID 2, 5, 22, 45 и 53) перенесены в `dev/experimental`. В 12 полных проверках остальные стратегии вместе открыли с первой попытки все те же адреса.
- Новая установка начинает с `SOFT-STUN2`. В 14 парных проверках у него было меньше ухудшений на обычных сайтах, чем у прежней основной `CORE-STUN`. В 17 профилях объединены совпадающие правила для голоса Discord.

- У всех стратегий появились короткие коды в меню, CLI и новых отчётах. Например, `CORE-STUN`, `FS-EXP` и `WHITE-03`. При выборе можно ввести код или прежнее имя.

- Нумерация Rust-линейки начинается с `v0`; меню, CLI, отчёты и архив используют единый номер версии.

- Нативный `winws2` собирается через LLVM MinGW и штатный Windows `tar.exe`. Команда `cargo zapret package --candidate` упаковывает проверенный движок во временной копии.
- Нативный ZIP собирается без Cygwin. Контроллер понимает прежние манифесты, сохраняет копию старой DLL перед удалением при обновлении и восстанавливает её при откате. Переходный архив сохраняет совместимость с прежним контроллером.
- Добавлена нативная Windows-сборка winws2 с LuaJIT, zlib и библиотекой zapret-wincompat на Rust. Проверки запускают настоящий движок без cygwin1.dll и проверяют Unicode-пути, файловые операции, таймеры и ограниченный токен.
- Расчёты из lua/fooling.lua перенесены в Rust ABI. Автотесты используют зафиксированные результаты 63 сценариев PowerShell и 15 исторических A/B-журналов; CI проверяет Cygwin и нативную Windows-сборку.
- Проверка установки EXE выполняет замену открытых образов в отдельном TEMP-пакете.

- Память стратегий, TTL/LRU, проверка контекста сети, защита старых соединений, решения детекторов и индекс активных хостов перенесены в Rust. В Lua остаётся связь с таблицами, таймерами и файловым API движка. DLL закреплена хешем и версией узкого API; общий FFI не включается. Проверки настоящего LuaJIT-движка работают без драйвера и прав администратора.
- Исторические A/B-журналы, PNG-превью настоящего Rust-меню и сценарии запуска/восстановления перенесены в `cargo zapret`. Старая математика A/B сверяется с PowerShell-эталоном. При подготовленном обновлении новое ядро устанавливается во время следующего запуска/перезапуска; неудачная установка откатывается.

- Лаборатория стратегий перенесена в Rust. Сохраняются очереди и отчёты, сетевые проверки идут через общий native worker с исходным POST-файлом и контролем времени, игры, VPN и живости движка. Добавлен безопасный `lab --plan-only`. Неверная строка отклоняет всю очередь.
- Замеры CPU/RAM, Lua memory benchmark и проверки установки открытого EXE, пакета, BAT-меню и HTTP/TLS перенесены в `cargo zapret`. Python, Lupa и OpenSSL больше не нужны основному native CI. Прежние скрипты оставлены как совместимые входы и исторические эталоны.

- Добавлен встроенный HTTP/3-клиент на Rust для Windows без нужных возможностей WinHTTP. Проверка использует Quinn, rustls и системную проверку сертификатов.
- Сборка, установка EXE, сбор лицензий и конвертер стратегий Flowseal перенесены в `cargo zapret`. Установка готовит все EXE заранее и восстанавливает предыдущие файлы при ошибке замены.
- Транспорт TG WS Proxy Flowseal v1.11.4 перенесён на Rust и включён в `zapret-rust.exe`. Подключение Telegram Desktop сохраняет прежний порт и secret. Доступны WebSocket, резервные CF WebSocket и HTTP/2 для медиа, а также TCP.
- Программа, меню, установочные файлы и архив теперь называются `zapret-rust`. Старые регистрации службы и задач распознаются при переносе установки.

## zapret 2.2 — 10 ноября 2026

- Добавлена отдельная диагностика Discord Voice. Она наблюдает UDP-события процессов Discord, проверяет отдельный контрольный STUN-сервер и сохраняет подтверждение двустороннего звука пользователем. Сетевые события, срабатывание профиля и качество звука не смешиваются. Захват ограничен по времени и объёму, обход не перезапускается.
- В Инструментах добавлена отдельная диагностика DNS → TCP → TLS → HTTP на текущем подключении. Проверяет до двух IPv4 и двух IPv6, повторяет попытки и сохраняет этап, исходный сигнал, время и ошибки сертификата. .NET/Schannel проверяет имя и доверие сертификату; HTTP-проба читает ограниченные заголовки HEAD. Противоречивые и неполные результаты сохраняют неопределённость, вывод о блокировке провайдером не делается.
- Проверка сертификата отдельно отмечает, был ли сертификат вообще получен для проверки. Незавершённые DNS-пробы и незапущенные цели сохраняются при отмене. Имена каталогов передаются DNS-процессу как данные, включая пути с типографскими кавычками.
- В Инструментах добавлена проверка текущего подключения браузером, HTTP/2 и HTTP/3. Доступен быстрый автоподбор с дополнительной проверкой после восстановления подключения. Временный профиль Edge/Chrome изолирован от личного браузера; сохраняются фактический протокол, завершение основного документа, HTTP-код, неизвестные и недоступные проверки. HTTP/3 curl проверяется без отката к TCP при наличии поддержки. Отчёты сохраняются отдельно от TCP-рейтинга.
- Параллельные проверки публикуют последние JSON/TXT-отчёты под общей блокировкой. Ошибка замены второго файла возвращает предыдущую пару; именные отчёты каждого прогона сохраняются отдельно.
- Быстрый автоподбор начинает с представителей TCP-семейств, основной и новых непроверенных стратегий. После полного покрытия проверяемых адресов без ухудшения контрольных сайтов уточняет до двух близких вариантов. Неполные или неопределённые результаты расширяют проверку на оставшийся пул. План сохраняет фактически измеренные и отложенные ID. Полный режим и несколько раундов измеряют весь выбранный набор.
- Пробы автоподбора читают до 64 КБ тела ответа, включая ответы сервера, игнорирующего Range. В журнале и подробном отчёте достижение целевого объёма отмечается отдельно от полного HTTP-ответа.
